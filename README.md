# قائمة الطعام الرقمية (Digital Menu)

موقع قائمة طعام رقمية بتصميم عصري ومتجاوب مع كل الأجهزة، يتكوّن من:

- **صفحة الزبون** `/` : تصنيفات مع عدّاد، بحث فوري بالاسم أو المكوّن، نافذة تفاصيل الطبق، سلة طلب محفوظة، اختيار «على الطاولة / توصيل» مع الاسم والهاتف والعنوان، تأكيد الطلب، ومتابعة حالة الطلب لحظيا.
- **لوحة التحكم** `/admin/` : صفحة دخول بهوية المطعم، نظرة عامة وإحصائيات، الأطباق، الفئات، رموز QR للطاولات، المظهر والألوان، الإعدادات، والطلبات مع إشعارات وتصدير.

لا يحتاج أي مكتبات خارجية (لا `npm install`). المطلوب فقط **Node.js 18 أو أحدث**.

## التشغيل

```bash
node server.js          # أو: npm start
```

ثم افتح:

- القائمة: http://localhost:3000
- لوحة التحكم: http://localhost:3000/admin/

**كلمة المرور الافتراضية: `admin123`** — غيّرها فورا من الإعدادات، أو شغّل الخادم بكلمة مرور مخصصة:

```bash
ADMIN_PASSWORD="كلمة-مرور-قوية" PORT=8080 node server.js
```

(المتغير `ADMIN_PASSWORD` يُستعمل فقط إلى أن تُغيَّر كلمة المرور من لوحة التحكم.)

## المزايا

### صفحة الزبون

- تصميم متجاوب بالكامل (هاتف صغير، هاتف كبير، تابلت، لابتوب، شاشة كبيرة) مع دعم `safe-area` لهواتف الحواف المنحنية.
- بحث فوري في الأسماء والوصف والمكونات، وتصفية بالفئة (تُخفى الفئات الخالية تلقائيًا)، مع خلفيات هادئة متناسقة مع كل مظهر وصور أطباق مقصوصة بتركيز أفضل.
- نافذة طبق بتفاصيل ومكونات وكمية، وسلة تُحفظ في المتصفح (منفصلة لكل طاولة).
- اختيار **طريقة الطلب**: «على الطاولة» (اسم + هاتف اختياري) أو «توصيل» (اسم + هاتف + عنوان إلزامي)، مع حفظ البيانات للطلب التالي.
- زر داخل **حقل العنوان** (على يساره): «إرسال موقعي الحالي» عبر GPS أو «اختيار من الخريطة» (خريطة OpenStreetMap تفاعلية بدون أي مكتبة خارجية)، ثم يُكتب العنوان تلقائيًا وتُحفظ الإحداثيات مع الطلب.
- **حساب الفاتورة**: مجموع فرعي + رسوم توصيل + إجمالي، وتنبيه بالحد الأدنى للتوصيل، واختيار طريقة الدفع، ومدة التحضير المتوقعة (كلها من إعدادات اللوحة).
- **إلغاء الطلب** من صفحة المتابعة خلال 10 دقائق وبما أن التحضير لم يبدأ.
- إرسال الطلب ثم **متابعة حالته** (تم الاستلام → قيد التحضير → جاهز → منجز) مع شريط تقدم وتحديث كل 10 ثوانٍ.
- شريط تذكير بآخر طلب غير منتهٍ عند العودة للصفحة.
- شريط معلومات أسفل شعار المطعم: واتساب، إنستغرام، فيسبوك، اتصال هاتفي، ساعات العمل وعنوان يُفتح على الخريطة (كلها أيقونات تُخفى تلقائيا إن لم تُضبط).
- دعم العمل دون اتصال بعد أول زيارة (PWA + Service Worker + صفحة «لا يوجد اتصال») وإمكانية تثبيتها على الشاشة الرئيسية بأيقونات PNG.
- لا تُعرض أسماء لغات غير مفعّلة؛ الواجهة عربية حاليًا.
- تحسين الظهور في محرّكات البحث والشبكات الاجتماعية: وصف وعنوان ديناميكيان، وسوم Open Graph و Twitter، وبيانات منظّمة `Restaurant` (JSON-LD).
- صور الأطباق، شرائح فئات لاصقة أثناء التمرير، رابط «تجاوز إلى القائمة» لقارئات الشاشة، وخط Tajawal مستضاف محليا (بدون أي طلب لخدمات خارجية).

### لوحة التحكم

- **نظرة عامة**: طلبات اليوم، إيرادات اليوم، طلبات قيد العمل، الأكثر طلبا في 30 يوما، وآخر الطلبات.
- **قائمة الهاتف**: درج منزلق (Slide menu) بزر قائمة في شريط علوي ثابت، مع حجاب خلفي وإغلاق بالخلفية أو Esc أو زر ×.
- **الطلبات**: لوحة على نمط لوحات التحكم الحديثة — **جدول طلبات + لوحة تفاصيل جانبية**:
  - الجدول: صورة رمزية للزبون، رقم الطلب، الاسم ونوع الطلب والهاتف، شارة حالة قابلة للنقر، **زر سريع في كل صف لتحديث الوضعية دون فتح الطلب** (بدء التحضير / جاهزة / تسليم / إعادة الطلب)، الإجمالي، الوقت النسبي مع تنبيه أحمر للطلبات المتأخرة أكثر من 10 دقائق، وشريط لوني على الحافة حسب الحالة، وقائمة ⋮ (تفاصيل/طباعة/حذف). نفس الزر يظهر داخل بطاقات عرض الشبكة بنص واضح.
  - لوحة التفاصيل: رقم الطلب والحالة، الوقت الدقيق، طريقة الدفع، بيانات الزبون، أزرار اتصال/واتساب/خريطة، العنوان، أصناف الطلب بصورها وأسعارها، تفصيل الفاتورة، وزر الانتقال للمرحلة التالية مع الطباعة والحذف وتغيير الحالة الكامل.
  - **إيصال طباعة أنيق** (80 مم / A4): شعار المطعم واسمه وبيانات التواصل، رقم الطلب والتاريخ والوقت ونوع الطلب، بيانات الزبون والعنوان وطريقة الدفع، جدول الأصناف بالكمية والسعر والمجموع، ثم المجموع الفرعي ورسوم التوصيل والإجمالي، مع الملاحظة وتذييل الشكر. يُطبع من زر الطباعة في لوحة التفاصيل أو من قائمة ⋮.
  - **تحديد متعدد** بمربعات اختيار مع شريط إجراءات جماعية (تغيير الحالة، تصدير المحدد، حذف).
  - بحث فوري، تصفية بالحالة والنوع والفترة، وترتيب (الأحدث/الأقدم/الأعلى قيمة/الحالة)، ترقيم صفحات، وعدّاد بقيمة إجمالية.
  - تصميم متجاوب: تبقى لوحة التفاصيل بجانب الجدول على الشاشات العريضة، وتتحول إلى درج منزلق على الشاشات الأضيق من 1280px، ويتحول الجدول إلى صفوف مبسّطة على الهاتف (بدون قصّ الأسماء).
  - **تبديل بين عرض الجدول وعرض الشبكة** (بطاقات مصغّرة متساوية الارتفاع للتصفح السريع، ويُحفظ اختيارك).
  - تحديث تلقائي كل 12 ثانية، جرس تنبيه وإشعارات نظام، وتصدير CSV (محمي من حقن الصيغ).
- **الأطباق**: بحث، إضافة، وتعديل داخل **نافذة منبثقة**، نسخ، حذف، صورة، مكونات، توفّر، و**إعادة الترتيب** بالأسهم (لوحة المفاتيح مدعومة).
- **الفئات**: إضافة، إعادة تسمية، إخفاء/إظهار، وإعادة ترتيب.
- **رموز QR**: رابط مخصص أو عنوان الموقع الحالي، عدد الطاولات، تحميل SVG وطباعة.
- **المظهر**: لون رئيسي، شكل البطاقات، و**3 مظاهر جاهزة** لصفحة الزبون فقط:
  - **دافئ** — الخلفية الكريمية الأساسية بلون المطاعم.
  - **ليلي** — خلفية داكنة مريحة للعين مع لون مميز فاتح.
  - **عصري** — ألوان باردة وزوايا أنعم.
  المظهر يغيّر خلفية صفحة الزبون وبطاقاتها وزواياها ولوحته اللونية، ولا يمسّ لوحة التحكم إطلاقًا. يمكن بعد اختيار المظهر تعديل اللون أو الرجوع إلى «دافئ» لاستعمال لون المطعم الأساسي.
- **الإعدادات**: صورة المطعم (زر إضافة/تغيير/إزالة تظهر بجانب الاسم في القائمة واللوحة)، واتساب/إنستغرام/فيسبوك، بيانات المطعم، رسوم التوصيل والحد الأدنى ومدة التحضير وطرق الدفع، تشغيل/إيقاف الطلبات وإظهار الأسعار، تغيير كلمة المرور، **نسخة احتياطية كاملة** (قائمة + طلبات + إعدادات) و**استعادتها من ملف**، وتنظيف الصور غير المستعملة. تنبيه دائم يظهر ما دامت كلمة المرور الافتراضية مستعملة.

## رموز QR

من تبويب «رموز QR» حدّد عدد الطاولات (ويمكنك تحديد رابط الموقع `baseUrl`). كل رمز يفتح القائمة برقم الطاولة (`/?table=3`).
إن تركت الرابط فارغا فسيُستعمل عنوان الموقع الذي فُتحت منه اللوحة، لذلك **افتح اللوحة من الدومين النهائي** قبل طباعة الرموز.

## النشر على الإنترنت

> **GitHub Pages لا يصلح لهذا المشروع**: Pages يقدّم ملفات ثابتة فقط، ومشروعنا خادم Node.js يوفّر `/api/menu` و`/api/orders` ورفع الصور وحماية لوحة التحكم. الصفحة ستُفتح لكن القائمة والطلبات لن تعمل. لذلك انشر المشروع على منصّة تشغّل Node.

### الخيار 1 — Render (الأسهل، مجاني)

1. سجّل في <https://render.com> بحساب GitHub.
2. **New +** ← **Web Service** ← اختر المستودع `digital-menu`.
3. الإعدادات:
   - Language / Runtime: **Node**
   - Build Command: `echo "no build step"` (لا توجد تبعيات)
   - Start Command: `node server.js`
   - Instance Type: **Free**
4. **Create Web Service** وانتظر دقيقة، ستحصل على رابط مثل `https://digital-menu-xxxx.onrender.com`.
5. افتح `/admin/` بكلمة المرور الافتراضية `admin123` ثم **غيّرها فورًا** من الإعدادات.
6. اضبط `baseUrl` في الإعدادات على الرابط النهائي ثم اطبع رموز QR.

بدلاً من الإعداد اليدوي يمكن استخدام الملف الجاهز `render.yaml` عبر **New + ← Blueprint**.

**تنبيهان مهمان للخطة المجانية**
- الخدمة «تنام» بعد نحو 15 دقيقة خمول، وأول زيارة بعدها تستغرق 20–50 ثانية.
- نظام الملفات مؤقت: الطلبات وكلمة المرور والصور المرفوعة قد تُفقد عند إعادة النشر أو إعادة تشغيل الخدمة. للحفظ الدائم أضف **Disk** (خطة Starter) واضبط مساره على `/opt/render/project/src/data`، واحتفظ بنسخة احتياطية دورية من لوحة التحكم ← الإعدادات ← «نسخة احتياطية».

### الخيار 2 — Cloudflare Workers (نسخة كاملة من الخادم)

فرع `cloudflare-workers` يحتوي نسخة تعمل **بالكامل** على Cloudflare: نفس الواجهة، نفس لوحة التحكم، نفس الـ API — لكن بدون Node.js. التخزين: **D1** لقاعدة البيانات (القائمة، الإعدادات، الطلبات، الجلسات) و**KV** للصور المرفوعة.

```bash
git clone https://github.com/Youssefidry/digital-menu.git
cd digital-menu
git checkout cloudflare-workers

npx wrangler login                       # يفتح المتصفح لتأكيد الحساب
npx wrangler d1 create digital-menu      # انسخ database_id إلى wrangler.toml
npx wrangler kv namespace create UPLOADS # انسخ id إلى wrangler.toml
npx wrangler d1 execute digital-menu --remote --file=migrations/0001_init.sql
npx wrangler deploy
```

بعد النشر تحصل على رابط `https://digital-menu.<اسم-حسابك>.workers.dev`، وتفتح لوحة التحكم على `/admin/` بكلمة المرور `admin123` ثم تغيّرها فورًا، وتضبط `baseUrl` ثم تطبع رموز QR.

- **لا تنام الخدمة** ولا تحتاج قرصًا دائمًا، والبيانات تبقى محفوظة في D1.
- **الأمان**: كلمة المرور تُخزَّن بـ PBKDF2-SHA256 مع ملح عشوائي، الجلسات في D1 لمدة 12 ساعة، تحديد معدل الطلبات، ورؤوس CSP/HSTS.
- **الدومين الخاص**: Workers ← Settings ← Domains & Routes ← Add custom domain.
- **تحديث لاحقًا**: `npx wrangler deploy` فقط.
- **حدود الخطة المجانية**: 100 ألف طلب يوميًا، D1 بحجم 5GB، KV بـ 100 ألف قراءة يوميًا — أكثر من كافية لمطعم.
- أول تشغيل يستخدم `data/menu.json` كبيانات أولية، وأي تعديل من لوحة التحكم يُحفظ في D1.

### الخيار 3 — Railway أو Koyeb

- **Railway**: New Project ← Deploy from GitHub ← اختر المستودع؛ يكتشف Node تلقائيًا ويشغّل `npm start`. أضف Volume على `/app/data` لحفظ الطلبات.
- **Koyeb**: Create Service ← GitHub ← Build: Buildpack ← Run: `node server.js`، وأضف Volume على `/app/data`.

### الخيار 4 — سيرفر خاص (VPS) مع دومين

```bash
git clone https://github.com/Youssefidry/digital-menu.git
cd digital-menu
npm i -g pm2
pm2 start server.js --name menu
pm2 save && pm2 startup
```

ثم ضع Nginx (أو Caddy) كـ reverse proxy إلى المنفذ `3000` مع شهادة HTTPS من `certbot` — HTTPS ضروري لحماية كلمة مرور اللوحة ولتفعيل Service Worker. واحتفظ بنسخة احتياطية دورية من `data/` و`public/uploads/`.

### تشغيل عبر Docker

```bash
docker build -t digital-menu .
docker run -d -p 3000:3000 -v "$PWD/data:/app/data" -v "$PWD/public/uploads:/app/public/uploads" --name menu digital-menu
```

### دومين خاص

- في Render: Settings ← Custom Domain ← أضف نطاقك واتبع تعليمات CNAME.
- بعد ربط الدومين افتح اللوحة منه، اضبط `baseUrl`، ثم أعد طباعة رموز QR حتى تشير إلى العنوان الجديد.

> ملاحظة: المستودع عام (Public) لكن **بيانات التشغيل لا تُرفع**: `data/auth.json` و`data/orders.json` مستثناة في `.gitignore`، لذلك كلمة مرور كل تثبيت تبقى خاصة به.

## واجهة API

| الطريقة | المسار | الوصف |
| --- | --- | --- |
| GET | `/api/menu` | القائمة العامة (الفئات الظاهرة والأطباق المتوفرة) |
| POST | `/api/orders` | إنشاء طلب: `{ type: 'dinein'|'delivery', table, name, phone, address, lat, lng, note, items }` (محدود المعدل) |
| GET | `/api/order/:id` | حالة طلب واحد (لمتابعة الزبون) |
| GET | `/api/geo/reverse?lat=&lon=` | تحويل الإحداثيات إلى عنوان عربي (وسيط Nominatim مع تخزين مؤقت) |
| GET | `/api/qr?text=` | توليد رمز QR كـ SVG |
| POST | `/api/login` | تسجيل دخول الأدمن |
| GET | `/api/admin/menu` | القائمة الكاملة (أدمن) |
| PUT | `/api/settings` | تحديث الإعدادات (أدمن) |
| POST | `/api/password` | تغيير كلمة المرور (أدمن) |
| POST | `/api/upload` | رفع صورة (أدمن) |
| POST | `/api/order/:id/cancel` | إلغاء الزبون لطلبه خلال 10 دقائق (قبل بدء التحضير) |
| GET/POST/PUT/DELETE | `/api/dishes`, `/api/categories` | إدارة الأطباق والفئات (أدمن) |
| POST | `/api/dishes/reorder` | إعادة ترتيب الأطباق `{ ids: [...] }` (أدمن) |
| GET | `/api/orders` | كل الطلبات (أدمن) |
| PUT/DELETE | `/api/orders/:id` | تغيير حالة/حذف طلب (أدمن) |
| GET | `/api/backup` | تنزيل نسخة احتياطية كاملة (أدمن) |
| POST | `/api/restore` | استعادة من نسخة احتياطية (أدمن) |
| POST | `/api/cleanup` | حذف الصور غير المستعملة (أدمن) |

حالات الطلب: `new` → `preparing` → `ready` → `done` (أو `canceled`).

## الموقع والخرائط

- الخريطة تُحمّل بلاطات OpenStreetMap مباشرة (`tile.openstreetmap.org`) وتعمل بدون أي مكتبة أو مفتاح API.
- تحويل الإحداثيات إلى عنوان يتم عبر الخادم (`/api/geo/reverse` ← Nominatim) مع تخزين مؤقت، فإن انقطع الإنترنت يبقى بالإمكان إرسال الطلب ويُكتب العنوان كإحداثيات.
- **GPS** يعمل على `https://` أو `localhost` فقط (قيد المتصفحات)؛ عند الفتح عبر `http://` من هاتف على الشبكة المحلية سيظهر تنبيه ويبقى خيار الخريطة متاحًا.
- العنوان المحفوظ يظهر في لوحة التحكم كرابط يفتح الإحداثيات الدقيقة على خرائط Google.

## ملاحظات تقنية

- البيانات محفوظة في ملفات JSON، وهذا مناسب لمطعم واحد بحركة عادية. لعدة فروع أو حركة كبيرة يلزم ربطه بقاعدة بيانات.
- جلسات الأدمن محفوظة في الذاكرة (تنتهي بعد 12 ساعة أو عند إعادة تشغيل الخادم)، وتسجيل الدخول محمي من التخمين (5 محاولات ثم انتظار 5 دقائق).
- الطلبات تُحدَّث تلقائيا في لوحة التحكم كل 12 ثانية (بدون WebSocket).
- خط Tajawal مستضاف محليا في `public/fonts/` (license: SIL OFL داخل `LICENSE-THIRD-PARTY.txt`)، فلا حاجة لاتصال بخدمات خارجية.
- الاستجابات النصية تُضغط بـ **gzip** وتُدعم إعادة التحقق عبر **ETag** (استجابة 304) لتسريع التحميل.
- عند تجاوز 1000 طلب تُنقل الأقدم تلقائيا إلى `data/orders-archive.json` كي لا تثقل الواجهة.
